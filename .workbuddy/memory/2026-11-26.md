# 2026-11-26

## RAG 流式（source / message / done / error）

- 新增 `app/services/rag_stream_service.py`：`stream_rag_answer(request, llm_provider, model=None)`，链路 检索 → `source`×N → LLM `stream_chat` → `message`* → `done`。
  - `source` 事件 payload：`index`（与回答里的 `[n]` 对齐）、`document_id`、`title`、`score`。
  - `build_retrieved_context()` 拼成 `[1] 标题：内容`，正好喂给 RAG prompt 的 `{retrieved_context}`。
  - 复用 `RAG_QA_PROMPT_V2`（强制引用编号），所以正文里的 `[n]` 能和 source 的 index 对上。
  - 检索为空时不调模型，直接 message=`知识库中暂未找到相关信息。` + `done.finish_reason="no_source"`。
  - 异常：`LLMProviderError` → `error` 事件 code=RAG_QUERY_FAILED(50003)。
- 新增端点 `POST /api/v1/rag/stream`（`app/api/v1/rag.py`）：StreamingResponse + 与 chat 一致的 is_disconnected / CancelledError / shield aclose 处理；需要请求头 `x-api-key` 与 `x-workspace-id`（后者由 `get_workspace_id` 强制）。
- `tests/test_rag_stream.py`：8 个离线用例（source 顺序与字段、done.source_count、上下文编号进 prompt、用到 v2 引用规则、空检索不调模型、error 事件码、context builder）。

### 踩坑

- `alembic`/`uvicorn` 这类长驻进程要用 run_in_background，`cmd &` 在工具调用结束后会被回收（表现为 curl exit=7 connection refused）。
- `/rag/stream` 挂在 `rag_router` 下，整个 router 带 `Depends(verify_api_key)`，所以必须带 `x-api-key`。


## messages 表新增 status（completed / failed / interrupted）

- `app/models/message.py`：`status` 列 `String(20)`，`nullable=False`、`default="completed"`、`server_default="completed"`、`index=True`。存字符串而非 DB 枚举，后续加状态不用改类型。
- `app/schemas/chat.py`：新增 `MessageStatus(str, Enum)` — COMPLETED / FAILED / INTERRUPTED。
- 迁移：`alembic revision --autogenerate -m "add message status"` → `1861181417bc`（down_revision `f93d5b244956`），已 `alembic upgrade head` 并在 information_schema 里确认列 + 默认值 `'completed'::varchar` 生效。
- 落库时机统一收口到 `stream_chat_with_ai` 的 `finally`：`status` 默认 COMPLETED，`except (GeneratorExit, asyncio.CancelledError)` → INTERRUPTED（重新 raise），`except LLMProviderError` / `except Exception` → FAILED；保存用 `anyio.CancelScope(shield=True)` 包住，保证被取消时也能写库。
- `chat_service.py`（非流式）模型异常时调 `save_failed_messages()` 写 user + assistant(status=failed, content="")；正常路径显式 `status=COMPLETED`。
- `conversation_repository.add_message(..., status=...)`，默认 completed。

### 踩坑

- 中断发生在第一个 token 之前时 `full_answer` 是空串，会写出一条 `content=""` 的 interrupted 记录；而 `ChatMessage.content` 有 `min_length=1`，读历史会直接 ValidationError。解决：`get_messages` 过滤 `status != failed AND content != ""`（失败消息只做排查，不进历史）。
- 只过滤 status 不够，必须同时挡空内容，否则历史接口 500。
